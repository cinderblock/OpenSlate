# Group C: state results feeds, 2026-11-03 general

Researched 2026-11-10, about 3:00 to 4:00 PM PST (23:00 to 00:00Z). One line per state: code, status, platform, main feed URL, what a programmer needs to know. Details and fixtures are in `<code>/findings.json`.

- **ma** | none | none | (no feed) https://www.sec.state.ma.us/divisions/elections/voting-information/announcing-certifying.htm | The Secretary's site says "We do not publish unofficial election results"; certified results appear weeks later in the PD43+ archive (https://electionstats.state.ma.us/), which today lists only 2026 primaries and specials.
- **mi** | works | custom-text | https://mvic.sos.state.mi.us/VoteHistory/GetElectionResultFile?electionId=707 | One tab-delimited file, one row per candidate per county and no statewide total rows, so sum the 83 counties yourself; the host is behind Cloudflare, which challenged the relay User-Agent on the HTML page but served this file, and the state posts it only once counties have reported, not through election night.
- **mn** | works | custom-text | https://electionresultsfiles.sos.mn.gov/20261103/allracesbycounty.txt (plus Governor.txt, ussenate.txt, ushouse.txt, stsenate.txt, LegislativeByDistrict.txt, ConstAmend.txt in the same folder) | Semicolon-delimited files with no header row and no timestamp inside (use Last-Modified); the folder is the election date, and the per-office files already carry district totals with precincts reporting in columns 12 and 13. The HTML site is behind a Radware captcha but the file host is open.
- **ms** | none | none | (no feed) https://www.sos.ms.gov/elections-voting/election-results | The Secretary of State lists certified results only (newest: the March 2026 primaries); counties do not have to send results to the state until the week after the election.
- **mo** | html-only | html-only | https://enr.sos.mo.gov/ (election id 750007086, sent in a form POST) | Results appear only after an ASP.NET form post, which I did not submit, so no 2026 numbers were seen; Cloudflare refuses any URL with a query string or outside three page paths, to browsers too. The race list and ids are readable at /PickaRace.aspx.
- **mt** | works | bpro-totalvote | https://esersws.mt.gov/ResultsAjax.svc/GetMapData?type=FED&category=SW&raceID=0&osn=0&county=0&party=0 (repeat with type = PSC, SCJ, JUD, SENATE, HOUSE, BQ) | Seven JSON GETs cover all 146 contests, with `Access-Control-Allow-Origin: *`; `osn` and `party` must be 0 or the answer is `{"d":null}`, and the last-updated time is only in the HTML page.
- **ne** | works | bpro-totalvote | https://electionresults.nebraska.gov/resultsCSV.aspx?text=All&type=All&map=CTY | One CSV with every contest (463); the title is the same for every district so key on RaceID and AreaNum, precincts come as an Excel formula `="1322/1322"`, and CurrentDateTime is the server clock, not the last update.
- **nv** | works | custom-json | https://silverstateelection.nv.gov/results-config.json -> manifest.json -> objects/<sha256>.json | A new content-addressed JSON feed: read results-config.json, then the manifest, then `manifest.overview.path` for all 372 contests with totals; object URLs change with every release. The HTML site is behind an Imperva captcha but the JSON answered the relay User-Agent.
- **nh** | blocked | other:xlsx-workbooks | https://www.sos.nh.gov/2026-general-election-results (76 files like .../media_document/2026-ge-governor-summary.xlsx) | No live count: per-office Excel workbooks laid out for people are posted over the days after the election, and Akamai refuses curl with any User-Agent (403), so only a real browser can fetch them.
- **nj** | none | none | (no feed) https://www.nj.gov/state/elections/election-night-results.shtml | The Division "does not post any official or unofficial results on Election Night" and instead links 21 county sites, 16 of them Clarity ENR (Atlantic verified: .../NJ/Atlantic/127487/current_ver.txt, CORS `*`); the state's own daily PDFs count ballots, not votes per candidate.
