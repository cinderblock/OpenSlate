# Group D: state results feeds (2026-11-03 general), researched 2026-11-10

One line per state: code | status | platform | main feed URL | what a programmer needs to know.

- nm | works | bpro-totalvote | https://electionresults.sos.nm.gov/resultsCSV.aspx?text=All&type=STATE&map=CTY | One CSV for the whole election, but key contests on RaceID (district is in the AreaNum column, every US House row is just "United States Representative"), each data row has an extra trailing comma, no CORS, and the update time is only in the home page HTML.
- ny | html-only | html-only | https://nyenr.elections.ny.gov/HomeNoJS.aspx | All 253 contests are on one 1.30 MB HTML page; it must be fetched WITHOUT an Origin header (Origin triggers a Cloudflare challenge), titles are bare districts ("1st Congressional District"), and each candidate has one row per party line (fusion) with a rowspan name cell.
- nc | works | custom-json | https://er.ncsbe.gov/enr/20261103/data/results_0.txt | Flat JSON array (text/plain), one object per candidate with the contest repeated on each row and every value a string; timestamps live in the sibling county.txt (row cid 0), and elections are listed in https://er.ncsbe.gov/enr/elections.txt.
- nd | works | other:knowink-totalresults | https://api.resultsnd.sos.nd.gov/Contest/GetContestResults?cId=north-dakota&electionID=348 | New JSON API (the old BPro site still shows 2024): results carry only ids, so join to /Contest/GetContestSearchList for contest and candidate names (names are space-padded); election list at /Election/GetElectionList?cid=north-dakota; CORS is *.
- oh | works | custom-xml | https://liveresults.ohiosos.gov/Api/v1/download?filename=VSSC1622XmlFileBlob | One 1.2 MB IEEE 1622.2 (NIST) ElectionReport XML with statewide and county counts; names are joined through CandidateId -> Candidate -> Person/Party, and GeneratedDate is a 12-hour clock mislabelled Z, so use the Last-Modified header.
- ok | blocked | custom-json | https://results.okelections.gov/OKERS/enrapi/GetCntyResults/20261103/0 | The load balancer 403s non-browser User-Agents and the API wants a Bearer token obtained by a PUT login with a key embedded in the app's JS; I did not log in, so no data was fetched and the path is read from the JS only.
- or | html-only | bpro-totalvote | https://results.oregonvotes.gov/resultsSW.aspx?type=FED&map=CTY | Results are server-rendered HTML, one page per contest type (FED, SWPAR, SENATE, HOUSE, SWNON, MCR, LMEA) with CORS *; the CSV/XML exports exist but only behind an ASP.NET form postback, which I did not submit, and "Precincts Reported" reads 0 on every contest.
- pa | works | custom-json | https://www.electionreturns.pa.gov/api/ElectionReturn/GetOfficeData?officeId=11&methodName=GetOfficeDetails&electionid=117&electiontype=G&isactive=1 | One request per office (ids 3, 11, 12, 13 from GetOfficeNames), every body is double-encoded JSON (a JSON string holding JSON), the district is an ordinal string not a number, and the HTML site is behind an Imperva/hCaptcha challenge though the API answered a plain client.
- ri | works | enhanced-voting | https://electionresults.ri.gov/results/public/api/elections/rhodeisland/2026StatewideGeneralElection/data | Standard Enhanced Voting /data document with CORS *; the elections list is at /results/public/api/jurisdictions/rhodeisland (not /api/elections/rhodeisland, which 404s), and party is baked into names ("John F. Reed (DEM)").
- sc | works | clarity | https://www.enr-scvotes.org/SC/127300/386661/json/en/summary.json | Clarity on the state's own host (current_ver.txt at /SC/127300/); titles have double spaces ("U.S.  House of Representatives, District  1"), PR is 0 and TP counts counties, STRAIGHT PARTY pseudo-contests must be dropped, and the recount is a separate election id (127592).
